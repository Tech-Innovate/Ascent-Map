# Ascent Map Engine Model

Ascent Map is organized around six logical engines plus an adapter plane. These are ownership boundaries, not deployment boundaries: a local V1 can implement all of them in one process while preserving their contracts.

## Engines

| Engine | Owns | Must not own |
|---|---|---|
| **State Engine** | Entity identity, events, evidence, claims, provenance, revisions, temporal semantics, canonical lineage | Retrieval ranking, prompts, model policy |
| **Memory Engine** | Durable recall structures, episodic/semantic/procedural memory, consolidation, lifecycle, forgetting, associative retrieval | Canonical truth admission |
| **Context Engine** | Query interpretation, candidate acquisition, dependency expansion, budgeting, compression, bounded immutable projections | Permanent memory or truth mutation |
| **Reasoning Engine** | Problem decomposition, reasoning strategy, hypothesis/test loops, selective depth, cognitive processor orchestration | Permission to change external reality |
| **Agency Engine** | Intent, authorization, planning, actions, execution attempts, effects, reconciliation | Epistemic truth by assertion |
| **Evaluation Engine** | Verification, benchmarks, adversarial evaluation, qualification, confidence calibration | Generating its own evidence and declaring itself correct |
| **Adapter Plane** | Models, tools, databases, crawlers, APIs, files, messaging systems, external protocols | Domain truth or business policy |

## Core separation

```text
Reality / external systems
          |
          v
     Adapter Plane
          |
          v
      Evidence
          |
          v
     State Engine
          |
      +---+-------------------+
      |                       |
      v                       v
 Memory Engine          Context Engine
                              |
                              v
                       Reasoning Engine
                         /           \
                        v             v
                 Evaluation       Agency
```

The direction of arrows describes information and authority flow, not necessarily synchronous calls.

## State before memory

Memory is not the canonical database. The State Engine determines what is known, observed, claimed, superseded, or unresolved. Memory may retain useful historical or procedural material, but recalling something does not make it true.

## Context is a projection

Context is a bounded, task-specific projection over state, memory, and retrieved material. It should be immutable for a reasoning step and disposable after use. Context selection must not silently rewrite durable state.

## Reasoning does not imply authority

The Reasoning Engine may form hypotheses, calculate service fit, identify missing evidence, or propose actions. It does not gain authorization merely because a conclusion is strong.

## Evaluation is independent

Evaluation should be capable of rejecting or qualifying reasoning outputs. Confidence is an evaluated property of evidence and inference, not a stylistic expression generated by the reasoning process.

## Agency records effects

Any action that changes external reality should be represented as an authorized execution attempt with an observable outcome. The system must distinguish:

```text
intent -> authorization -> attempt -> observed effect -> reconciliation
```

An action request is not evidence that the action succeeded.

## Adapter discipline

Adapters translate external representations into internal contracts. For example, a Google Maps scraper can emit an observation that a listing contains a phone number, rating, or website. It cannot directly create a canonical business profile or service recommendation.

## Prospect Intelligence mapping

The first domain maps onto the engine model as follows:

| Prospect Intelligence concern | Engine owner |
|---|---|
| Business identity, raw evidence, resolved facts | State Engine |
| Historical profile/evaluation recall | Memory Engine |
| Evidence selected for a prospect assessment | Context Engine |
| Signal derivation and service/channel interpretation | Reasoning Engine |
| Validation, fit confidence, contradiction handling | Evaluation Engine |
| Future approved outreach/action execution | Agency Engine |
| Google Maps, website crawlers, local models | Adapter Plane |

The first implementation may keep all of these inside one local application. The architectural requirement is ownership clarity, not microservices.
